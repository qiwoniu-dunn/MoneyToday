# MoneyToday 产品思考沉淀

## 产品本质

MoneyToday 表面上是一个实时收入计算器，但它真正提供的是一种“劳动反馈可视化”。

很多工作日里，劳动成果是延迟到账的：工资按月发，绩效按季度算，年薪按年感知。MoneyToday 把这种延迟反馈压缩到当下，让用户在一天中随时看到：

```text
我今天已经获得了一些真实的东西。
```

这也是它区别于记账、理财、薪资计算器的地方。

## 情绪价值原则

MoneyToday 的情绪价值不是鸡血，也不是攀比，而是温和地承认用户今天的努力。

因此它遵循几个原则：

### 只展示已经获得的

不展示“距离下一个还差多少”，因为这种表达容易把奖励变成压力。

正确方向：

- 今天的咖啡自由已经到账。
- 已经攒下一顿舒服的晚餐。
- 今天的努力已经换成一件实在的小礼物。

避免方向：

- 距离下一台手机还差多少。
- 今日目标只完成了百分之多少。
- 你还需要继续工作多久。

### 生活化而不是金融化

用户已经知道金额是多少，但金额本身很抽象。换算成生活物品后，收益会更容易被感知。

例如：

- 20 元可以是一杯奶茶。
- 50 元可以是一顿午餐。
- 200 元可以是一只不错的鼠标。
- 1000 元可以是一次短途旅行预算的一部分。

这些物品不需要金融级准确，只需要在生活经验上可信。

### 稳定但不重复

如果同一天界面不断跳出完全不同的物品，会显得随机和不可信；但如果每天都是同一句，又会很快失去新鲜感。

所以 1.0 采用：

- 同一天稳定轮换结果。
- 跨天更换候选文案和物品。
- 根据日薪档位和收入进度选择合理层级。

### 鼓励但不过度营销

文案应该像一个轻轻拍肩膀的提醒，而不是广告口号。

适合的气质：

- 温暖。
- 有一点幽默。
- 具体。
- 不贬低用户。
- 不制造焦虑。

## UI 设计原则

### 菜单栏里要克制

菜单栏是高频区域，不能抢戏。图标需要清晰、稳定、易识别。

1.0 最终选择钱袋图形，是因为它比抽象钱流更容易被用户在小尺寸下识别。

### Popover 里要有主次

主界面只保留最重要的三件事：

1. 今天已经赚到的金额。
2. 今天工作进度。
3. 已经换算成什么生活奖励。

设置、节假日同步、测试模式等低频功能都收进设置页。

### 数字要“活”

金额从每秒刷新提升到每 100ms 刷新，并显示 4 位小数，是为了让用户明显感到数字正在流动。

它不一定意味着真实薪资精确到小数点后四位，而是为了强化“正在赚”的感知。

## 1.0 的边界

MoneyToday 1.0 选择保持小而完整：

- 不做复杂财务统计。
- 不做税务计算。
- 不做多人账户。
- 不做云同步。
- 不做 App Store 发布。
- 不做实时物价联网查询。

这些边界让项目能快速到达一个可用、可发布、可反馈的状态。

## 后续方向

### 更完整的发布体验

- Apple 开发者签名。
- 公证。
- DMG 包。
- GitHub Release 自动化。

### 更丰富的奖励系统

- 更多物品池。
- 更多文案风格。
- 节日或特殊日期彩蛋。
- 用户可自定义奖励物品。

### 更适度的统计

可以增加“本周累计已赚”“本月累计已赚”等统计，但需要谨慎设计，避免从获得感变成 KPI 压力。

### 更强的本地隐私表达

MoneyToday 的年薪数据非常敏感，后续可以在 README 和设置页中更明确说明：

- 数据只保存在本机。
- 不上传薪资。
- 不做行为追踪。
