# MoneyToday 建设过程记录

## 2026-05-23：从想法到 1.0 发布

### 1. 初始想法

MoneyToday 的起点是一个很直接、也很有情绪价值的想法：

每天工作时，如果能在 Mac 顶部菜单栏里看到“今天已经赚到的钱”正在实时跳动，会带来一种即时反馈和满足感。

初始设想很简单：

- 用户输入年薪。
- App 根据工作日和工作时间计算今日收入。
- 如果是工作日，就从早上 9 点到晚上 19 点实时累加。
- 金额按秒甚至更高频率跳动。
- App 以 macOS 菜单栏小工具形态运行。

### 2. 产品方向确认

项目早期确认了几个重要方向：

- 这是一个本地小工具，不是大型财务软件。
- 菜单栏只放一个精致图标，不直接显示大段文字。
- 点击菜单栏图标后打开 popover。
- UI 要有“精致金融仪表”的感觉，不能像临时 demo。
- README 和产品界面都使用中文简体。
- 初版优先本机可运行，不处理 App Store、签名、公证等发布链路。

### 3. 技术方案落地

由于当前环境主要具备 Swift CLI，而不是完整 Xcode 项目流，因此采用：

- Swift Package Manager 管理项目。
- AppKit 创建 `NSStatusItem` 菜单栏入口。
- SwiftUI 构建 popover UI。
- 本地 `UserDefaults` 保存年薪、货币、工作时间、开机启动和测试模式。
- 节假日数据通过网络 API 获取并缓存，离线时降级使用缓存或周一到周五。

核心计算模型确定为：

```text
每日收入 = 年薪 / 当年工作日数量
每秒收入 = 每日收入 / 当天工作秒数
今日已赚 = 每秒收入 * 今天已经过去的工作秒数
```

### 4. 第一轮可运行版本

第一轮实现了：

- macOS 菜单栏 App。
- popover 主界面。
- 年薪和工作时间设置。
- 工作日收入计算。
- 节假日服务。
- 本地构建和 `.app` 打包。

这一版解决了“能不能跑起来”的问题，但用户体验上还有明显问题：

- 输入后没有明确保存和执行按钮。
- 设置区域长期暴露在主界面里。
- 部分界面不是中文。
- 图标不够好看。
- 菜单栏 popover 位置看起来不够贴近顶部菜单栏。
- 周末无法验收实时跳动效果。

### 5. 设置体验和图标迭代

根据反馈，后续迭代做了这些调整：

- 首次启动进入设置流程。
- 增加“保存并开始”按钮。
- 设置入口收进齿轮按钮。
- 产品界面改成中文简体。
- 增加测试模式，开启后忽略周末和节假日。
- 重新设计菜单栏图标方向，从抽象钱流逐步转向更明确的钱袋图标。
- 补齐 App 文件图标。

这一步把 MoneyToday 从“工程可用”推进到“产品可用”。

### 6. 主界面信息密度优化

主界面曾经有一个圆环进度条，同时下方还有直线进度条。后来判断圆环和直线表达重复，于是：

- 移除圆环进度条。
- 保留直线进度条。
- 将进度条改为绿色。
- 给金额展示腾出更多空间。
- 金额改为 4 位小数。
- 刷新频率从每秒提升到每 100ms。

这个改动让主界面更聚焦：打开后第一眼就是跳动的今日收入。

### 7. 节假日同步降噪

最初主界面展示了节假日同步状态和同步按钮。但节假日数据属于低频数据，一年中变化次数很少，主界面高频展示会显得过重。

因此后续确定：

- 主界面不展示同步按钮。
- 同步节假日只放在设置页。
- 同步由用户手动触发。
- 最近同步状态弱化展示。

这个决策让主界面从“工具后台”回到“获得感仪表”。

### 8. 情绪价值系统

项目中最关键的一次产品扩展，是加入“今天已经赚到了什么”。

早期讨论中明确了几个原则：

- 不显示“距离下一个还差多少”，因为这会制造焦虑。
- 只表达已经获得的东西。
- 文案要温暖、有鼓励感，不要死板。
- 换算物品要贴近中国大陆人民币生活语境。
- 同样金额每天也应该有不同表达，避免每天都看见同一句话。

于是实现了本地奖励物品池：

- 低日薪档：咖啡、奶茶、早餐、午餐、快餐、打车、电影等。
- 中日薪档：餐厅、按摩、外设、香水、耳机等。
- 高日薪档：运动相机、酒店、短途旅行、手机、电脑等。

并通过“日期 + 货币 + 年薪阶层 + 金额段位”稳定轮换文案：

- 同一天稳定，不会乱跳。
- 第二天变化，制造一点新鲜感。

### 9. 像素图和视觉打磨

奖励文案加入后，主界面仍然偏单调，于是增加了奖励物品对应的像素风图像。

后续又根据反馈继续打磨：

- 像素图从粗颗粒改为更精细的表现。
- 每类物品都有更具体的视觉表达。
- 菜单栏图标改为更完整、更接近正方形边界的实心钱袋。
- App 图标改为黄色底加钱袋图标。
- 让 Finder 中看到的 App 文件不再是系统默认占位图标。

### 10. 稳定性修复

过程中也遇到过几个实际问题：

- 设置页输入框无法编辑。
- App 能出现菜单栏图标但点击无法打开。
- popover 位置不符合预期。
- 图标资源生成后 macOS 显示不正确。

这些问题分别通过调整 SwiftUI 状态绑定、popover 管理、图标资源和打包脚本完成修复。最终本机可以正常启动、点击、设置和验收。

## 2026-05-29：1.1 试用归档与 1.2 奖励文案需求

1.1 试用版在奖励系统上继续推进：

- 奖励候选池扩展为 5 个日薪层级、10 个阶段、每阶段 6 个具体品牌商品候选，共 300 个候选。
- 300 个具体商品候选通过 `assetKey` 收敛到 47 张通用商品图，图片放在 `Sources/MoneyTodayApp/Resources/RewardsV2/final-47`。
- 早期强压到 `20x20` 再放大的图片过于模糊，已改为保留清晰 `512x512` PNG 作为 App 资源。
- 主界面奖励区继续使用芝麻小猫轻动效，并和当前商品图片组合展示。
- 1.1 已在本地重新打包 `.app`、`.zip`、`.pkg`，准备同步到 GitHub。

试用反馈也明确了 1.2 的文案方向：

- 奖励不是精确兑换，不应该透出商品的具体金额。
- 不要使用“约等于”“够换”“已获得”“档位”“点亮”“第 x/10”“奖励台”等任务感、成就系统感或价格换算感表达。
- 用户看到奖励时需要的是小确幸和心理安慰，不是对价格的较真。
- 奖励文案应保留今日已赚金额这个事实反馈，但商品只作为模糊的生活想象锚点。
- 1.2 将先围绕奖励文案口径重写，不改变 1.1 的 300 个候选商品和 47 张商品图资产结构。
