# MoneyToday 1.2.0 需求记录

## 背景

1.1 试用版已经把奖励池扩展到 300 个具体品牌商品候选，并用 47 张清晰像素风商品图承载视觉表达。试用后发现，当前文案仍然带有明显的“价格换算 / 阶段达成 / 任务系统”口吻。

MoneyToday 的奖励目标不是精确兑换，也不是告诉用户“已经获得了某个商品”。它应该提供一种更模糊、更温和、更贴近日常感受的心理安慰：今天的工作没有白熬，数字背后有一点具体生活可以想象。

## 1.2 目标

- 将奖励文案从“价格换算 / 档位达成”改成“模糊价值感 + 生活安慰”。
- 保留今日已赚金额作为产品核心事实反馈。
- 保留具体商品名作为生活想象锚点。
- 保留芝麻小猫的陪伴感，让奖励反馈更像温柔提醒，而不是成就系统。
- 不在 1.2 中扩大商品池或新增商品图品类，继续复用 1.1 的 300 个候选和 47 张商品图。
- 允许新增芝麻奖励区专用姿态素材，用于强化商品互动感。

## 禁止表达

1.2 奖励文案中不应出现这些表达方向：

- 商品具体金额。
- “约等于”。
- “够换”。
- “已获得”。
- “档位”。
- “点亮”。
- “第 x/10”。
- “奖励台”。
- 任何让用户觉得 App 在做精确价格承诺、任务进度判断或成就系统判定的表达。

## 保留表达

1.2 奖励文案应保留这些信息和氛围：

- 今日已赚金额。
- 当前商品或体验名。
- 芝麻陪伴感。
- “今天没白熬”的心理补偿。
- 小确幸、松一口气、可以想象一下的生活感。
- 对工作日的温柔承认，而不是鸡血、攀比或绩效压力。

## 推荐文案方向

文案可以接近这些感觉：

- “今天已赚 ¥168，芝麻觉得小米空气炸锅可以先进入幻想清单。”
- “今天已赚 ¥168，先不急着买，但这种小日子已经有一点轮廓了。”
- “今天已赚 ¥168，芝麻把小米空气炸锅放在旁边，提醒你这不是一串冷冰冰的数字。”
- “今天已赚 ¥168，离那种下班后能犒劳自己的生活又近了一点。”

这些示例只用于表达方向，正式实现时需要按品类生成更多自然模板。

## 验收标准

- 奖励区不展示商品价格。
- 奖励文案不出现禁止表达列表中的词语或等价说法。
- 低金额商品文案轻快、不夸张。
- 中高金额商品文案偏想象、期待、补偿感，不暗示用户已经买得起。
- 同一天同一阶段文案稳定，跨天或阶段变化仍保持新鲜感。
- 仍通过 `swift build --disable-sandbox` 和 `swift run --disable-sandbox MoneyTodayChecks`。

## 暂不包含

- 不新增商品候选。
- 不新增商品图品类。
- 不改变日薪层级、阶段数和候选选择规则。
- 不做商品价格实时联网校准。
